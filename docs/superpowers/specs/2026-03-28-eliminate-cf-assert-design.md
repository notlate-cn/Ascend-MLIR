# EliminateCfAssert Pass Design

**Date:** 2026-03-28
**Goal:** 用一个正式的 MLIR pass 替换 pipeline.py 中的 regex hack，在 torch-mlir 后处理阶段消除 `cf.assert` op。

---

## Problem Statement

torch-mlir 在 lowering 动态 shape broadcast 时，会为无法静态证明的维度相等关系插入运行时检查：

```mlir
%dim   = tensor.dim %arg0, %c0 : tensor<?xf16>
%dim_0 = tensor.dim %arg1, %c0 : tensor<?x?xf16>
%0 = arith.cmpi eq, %dim, %dim_0 : index
cf.assert %0, "mismatched size for broadcast"
```

这些 `cf.assert` 在我们的 pipeline 中造成两个问题：

1. **`afir-translate` 不认识 cf dialect**，遇到 `cf.assert` 直接报错
2. **当前的解决方式是 pipeline.py 中的 regex 文本替换**（step 7c），不可靠且位置过晚

---

## Design Decision：直接消除 vs. Lower 到 runtime check

### 为什么不 lower 成 AscendC runtime check（Trap）？

AscendC 提供了 `Trap()` API（`asc_TrapOp`），理论上可以将 `cf.assert` lower 成 `cf.cond_br` + `asc.trap`，保留运行时检查。但我们选择直接消除，原因：

1. **测试框架已保证 shape 合法性**：`TensorSpec` 通过符号名（如 `"M"`）确保多个 tensor 共享的维度使用同一个值实例化
2. **生产环境由 CANN 框架保证**：kernel 的 shape 由 host 侧 tiling 函数计算和分发，不存在用户随意传入不兼容 shape 的场景
3. **改动代价不成比例**：完整 lowering 需要验证 `afir-translate` 对 `asc.trap` / `cf.cond_br` 的 emit 支持，当前场景不需要

### 性能考量

即使保留 runtime check，开销也可忽略（一次标量比较 + 一次条件跳转，cold path 永不执行）。但既然不需要，就不生成。

## Architecture

### Pass 定义

| 属性 | 值 |
|------|------|
| 名称 | `EliminateCfAssertPass` |
| 注册名 | `--eliminate-cf-assert` |
| 作用域 | `mlir::func::FuncOp` |
| 代码位置 | `lib/Conversion/EliminateCfAssert/` |
| 依赖 dialect | `cf::ControlFlowDialect`, `arith::ArithDialect` |

### 核心逻辑

```
1. Walk function body，收集所有 cf::AssertOp
2. 对每个 AssertOp:
   a. 记录其 condition operand（通常是 arith.cmpi 的结果）
   b. Erase AssertOp
3. 对记录的 condition defining op:
   - 如果没有其他 user → erase（简单 DCE）
```

预估代码量：50-80 行 C++。

### Pipeline 位置

pass 放在 **torch-mlir 后处理阶段**——torch_to_linalg 输出之后、标准 linalg pipeline 之前：

```
step0:   torch_to_linalg
         ↓
── torch-mlir 后处理 ──────────────────
step0a:  --eliminate-cf-assert          ← 消除 broadcast assert
step0b:  --linalg-fold-unit-extent-dims ← 消除 expand_shape
── 标准 linalg pipeline ───────────────
step1:   --linalg-fuse-elementwise-ops
step2:   --transform-interpreter
step3:   --one-shot-bufferize
step4:   --ascendc-buffer-placement
step5:   --linalg-to-ascendc
step6:   --ascendc-parallelize
step7:   --ascendc-prepare-for-emit
step7b:  --canonicalize-cann-signature
step8:   afir-translate -mlir-to-cann
```

**越早消除越好**：后续所有 pass 都不需要处理这些无用的 cf op。

### 为什么不放在 prepare-for-emit 里？

`--ascendc-prepare-for-emit` 已经有类似的"afir-translate 不认识就在这里处理"的逻辑（如 lower `affine.min` → `arith.minsi`），但：

1. `cf.assert` 是 torch-mlir 特有的 artifact，不是通用 pipeline 问题
2. prepare-for-emit 已经很重（700+ 行），不应继续膨胀
3. 早期消除让中间 IR dump 更干净，方便调试

## Implementation Changes

### 1. 新建 pass 源文件

- `include/Conversion/EliminateCfAssert/EliminateCfAssertPass.h`
- `lib/Conversion/EliminateCfAssert/EliminateCfAssertPass.cpp`
- `lib/Conversion/EliminateCfAssert/CMakeLists.txt`

### 2. Pass 注册（Passes.td）

在 `include/Conversion/Passes.td` 中添加：

```tablegen
def EliminateCfAssertPass : Pass<"eliminate-cf-assert", "mlir::func::FuncOp"> {
  let summary = "Eliminate cf.assert ops (torch-mlir dynamic shape broadcast checks)";
  let description = [{
    Removes cf.assert operations generated by torch-mlir for dynamic shape
    broadcast validation. These runtime checks are unnecessary when the
    calling framework guarantees shape compatibility.

    Also performs simple DCE on the condition operand (typically arith.cmpi)
    if it has no other users after the assert is removed.
  }];
  let constructor = "mlir::afir::createEliminateCfAssertPass()";
  let dependentDialects = [
    "mlir::cf::ControlFlowDialect",
    "mlir::arith::ArithDialect"
  ];
}
```

### 3. pipeline.py 变更

- 在 step0b 之前添加 step0a 调用 `--eliminate-cf-assert`
- 删除 step 7c 的 regex hack（当前 pipeline.py:411-419）
- 更新 `_run_mlir_pipeline` docstring

### 4. CMakeLists.txt

在 `lib/Conversion/CMakeLists.txt` 中添加子目录。

## Future Considerations

如果未来需要保留 runtime check（如 debug 模式），可以：
1. 将此 pass 改为可选（pipeline.py 中通过 flag 控制是否运行）
2. 新建 `--lower-cf-assert-to-ascendc` pass，将 `cf.assert` lower 成 `cf.cond_br` + `asc.trap`（AscendC 的 `Trap()` API）

但当前不需要。
