# Add+Mul+ReLU Fusion E2E Example Design

## Goal

Add an end-to-end example that exercises the `--vector-plan-codegen` pipeline on a 3-op elementwise fusion chain with dynamic 3D shapes, validating on the Ascend910B1 simulator.

## Architecture

Three `linalg` named ops (add, mul, generic-relu) on `<?x?x?xf32>` tensors flow through `--vector-plan-codegen`. The pipeline's new `linalg-generalize-named-ops` step converts them to `linalg.generic` before TileFuse, which collapses the 3D parallel axes into a single 1D axis and fuses all three ops into one tiled loop nest. `afir-translate --tiling-space-out` auto-generates `tiling_space.json` from the compiled MLIR; `run.sh` fills in the runtime manifest and invokes `runtime-session`.

## Computation

```
tmp[d0,d1,d2] = b[d0,d1,d2] * c[d0,d1,d2]
out[d0,d1,d2] = relu(a[d0,d1,d2] + tmp[d0,d1,d2])
             = max(a + b*c, 0)
```

All tensors: `<?x?x?xf32>`, fully dynamic. Example run uses shape `4×8×32 = 1024` elements.

## Pipeline Change

Add one pass at the start of `--vector-plan-codegen` in `lib/Conversion/VectorPlan/Pipeline.cpp`:

```cpp
// Before TileFuse: convert named ops (linalg.add, linalg.mul) to linalg.generic
pm.addNestedPass<func::FuncOp>(mlir::createLinalgGeneralizeNamedOpsPass());
pm.addNestedPass<func::FuncOp>(createVectorPlanTileFusePass());
// ...rest unchanged
```

This is a no-op for inputs that already use `linalg.generic`.

## Input MLIR

```mlir
func.func @add_mul_relu(
    %a: tensor<?x?x?xf32>,
    %b: tensor<?x?x?xf32>,
    %c: tensor<?x?x?xf32>,
    %out: tensor<?x?x?xf32>) -> tensor<?x?x?xf32> {
  %c0 = arith.constant 0 : index
  %c1 = arith.constant 1 : index
  %c2 = arith.constant 2 : index
  %d0 = tensor.dim %a, %c0 : tensor<?x?x?xf32>
  %d1 = tensor.dim %a, %c1 : tensor<?x?x?xf32>
  %d2 = tensor.dim %a, %c2 : tensor<?x?x?xf32>
  %tmp_empty = tensor.empty(%d0, %d1, %d2) : tensor<?x?x?xf32>

  // b * c
  %tmp = linalg.mul
    ins(%b, %c : tensor<?x?x?xf32>, tensor<?x?x?xf32>)
    outs(%tmp_empty : tensor<?x?x?xf32>) -> tensor<?x?x?xf32>

  // a + tmp
  %add_empty = tensor.empty(%d0, %d1, %d2) : tensor<?x?x?xf32>
  %add = linalg.add
    ins(%a, %tmp : tensor<?x?x?xf32>, tensor<?x?x?xf32>)
    outs(%add_empty : tensor<?x?x?xf32>) -> tensor<?x?x?xf32>

  // relu = max(x, 0)
  %result = linalg.generic {
    indexing_maps = [affine_map<(d0,d1,d2)->(d0,d1,d2)>,
                     affine_map<(d0,d1,d2)->(d0,d1,d2)>],
    iterator_types = ["parallel","parallel","parallel"]}
    ins(%add : tensor<?x?x?xf32>) outs(%out : tensor<?x?x?xf32>) {
  ^bb0(%in: f32, %unused: f32):
    %zero = arith.constant 0.0 : f32
    %r = arith.maximumf %in, %zero : f32
    linalg.yield %r : f32
  } -> tensor<?x?x?xf32>
  return %result : tensor<?x?x?xf32>
}
```

## Tiling Strategy

After `linalg-generalize-named-ops`, TileFuse sees 3 `linalg.generic` ops with identical 3D parallel iteration spaces. Collapse merges the 3 parallel axes into a single axis with extent `d0*d1*d2`. TilePlanGen generates:

| Param | Default | Role |
|-------|---------|------|
| `XBLOCK` | 128 | Elements per AiCore (outer tile) |
| `XBLOCK_SUB` | 16 | Inner pipeline tile |
| `dim_arg0_0..2` | — | Shape of `%a` |
| `dim_arg1_0..2` | — | Shape of `%b` |
| `dim_arg2_0..2` | — | Shape of `%c` |
| `dim_arg3_0..2` | — | Shape of `%out` |

`block_dim = ceil(d0 * d1 * d2 / XBLOCK)`

For shape `4×8×32`: `block_dim = ceil(1024 / 128) = 8`.

## run.sh Flow

```
Stage 1: afir-opt add_mul_relu.mlir --vector-plan-codegen → kernel.mlir
Stage 2: afir-translate -mlir-to-cann kernel.mlir
           -o kernel.cpp --tiling-space-out tiling_space.json
         python patch_tiling_space.py  # inject XBLOCK values
Stage 3: runtime-session --kernel kernel.cpp --kernel-kind vec
           --output artifact --name add_mul_relu
Stage 4: runtime-session --run-manifest manifest.json --run
           # manifest has block_dim computed from actual shape
```

`patch_tiling_space.py` (inline in run.sh as python snippet) adds `"values": [128]` to XBLOCK and `"values": [16]` to XBLOCK_SUB. `block_dim_expr` is left empty (autotuner concern, not needed for E2E).

## Testing

**Lit test** (`codegen-add-mul-relu-e2e.mlir`) checks:
- `MLIR:` — fused into a single tiled loop body, no `linalg.generic` remains, TilingData struct has XBLOCK/XBLOCK_SUB/dim_arg fields
- `CANN:` — `struct TilingData`, `__aicore__ void add_mul_relu(`, `Mul(`, `Add(`, `Max(`

**E2E sim test** (`run.sh`) checks:
- `session.validation=pass` — numerics match NumPy `np.maximum(a + b*c, 0)`
- atol=1e-5, rtol=1e-5
